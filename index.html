Publish a website with GitHub Pages

GitHub Pages turns a folder of HTML, CSS, and JavaScript into a live website, for free. This guide takes you from nothing to a public URL in about ten minutes. (This page is hosted on GitHub Pages too.)

What GitHub Pages is

GitHub Pages is static site hosting built into GitHub. You put files in a repository, flip one setting, and GitHub serves them at a URL like username.github.io.

Static is the key word. Pages serves files exactly as they are: HTML, CSS, JavaScript, images, PDFs. It can't run server-side code like PHP, Python, or a database. Portfolios, project docs, résumés, blogs, and landing pages are all a great fit.

Before you start

  • A free GitHub account
  • At least one HTML file. The file that loads first must be named index.html (all lowercase)
  • A public repository if you're on the free plan

No HTML yet? Use this starter. Save it as index.html:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My First Site</title>
</head>
<body>
  <h1>Hello, world!</h1>
  <p>This site is hosted on GitHub Pages.</p>
</body>
</html>

Publish your first site

1

Create a repository

On GitHub, click + in the top-right corner, then New repository. Give it a name (for example my-site), set it to Public, and click Create repository.

2

Upload your files

On the new repo's page, click uploading an existing file (or Add file → Upload files). Drag in index.html and anything it uses, such as CSS files and images. Click Commit changes.

index.html must sit at the top level of the repo, not inside a subfolder.
3

Turn on Pages

Go to the repo's settings page and open the Pages section:

Settings → Pages

Under Build and deployment, set:

  • Source: Deploy from a branch
  • Branch: main, folder / (root)

Click Save.

4

Wait a minute, then visit

GitHub builds and deploys the site, usually within a minute or two. You can watch progress in the repo's Actions tab. Refresh the Pages settings screen and you'll see your live URL:

https://YOUR-USERNAME.github.io/my-site/

That's it. Your site is on the internet.

5

Update it anytime

Edit a file on GitHub (the pencil icon) or upload a new version, then commit. Every commit to main redeploys the site automatically.

Using git instead of the browser

Once you're comfortable, working locally with git is faster. From the folder that holds your site:

git init
git add .
git commit -m "First version of my site"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/my-site.git
git push -u origin main

Then enable Pages as in Step 3. Future updates are just:

git add .
git commit -m "Describe your change"
git push

User site vs. project site

The repository name decides your URL.

TypeRepo nameURL
User site
One per account		 username.github.io https://username.github.io/
Project site
As many as you want		 Anything, e.g. my-site https://username.github.io/my-site/

A user site makes a good personal homepage or portfolio. Project sites work well for individual projects, demos, or class assignments.

On a project site, links that start with / point to the root of username.github.io, not your project. Use relative paths like style.css or images/logo.png instead of /style.css.

Custom domains

If you own a domain, you can serve your site from it instead of github.io.

  1. In Settings → Pages, type your domain under Custom domain and save. GitHub adds a CNAME file to your repo.
  2. At your domain registrar, add DNS records. For a subdomain like www.example.com, add a CNAME record pointing to username.github.io. For an apex domain like example.com, use the A records listed in GitHub's custom domain docs.
  3. Once DNS resolves (minutes to a day), tick Enforce HTTPS.

Limits to know

  • Static files only. No server-side code or databases.
  • Public by default. Free accounts can publish from public repos; private-repo Pages needs a paid plan. Either way, the published site itself is public.
  • Size. Keep sites under about 1 GB. Bandwidth is capped softly at around 100 GB per month.
  • Not for commerce. GitHub doesn't allow running an online business or e-commerce site on Pages.
  • Never commit secrets. API keys, passwords, and tokens in your repo are visible to everyone.

Troubleshooting

I get a 404 page

Check three things: your file is named exactly index.html (lowercase), it sits at the root of the branch you picked in Settings, and the deploy has finished in the Actions tab. Also confirm you're visiting the right URL, including the repo name for project sites.

My CSS or images don't load

Most likely a path problem. File names on Pages are case-sensitive, so Logo.PNG and logo.png are different files. On project sites, avoid paths that start with /.

My changes don't show up

Wait for the deploy in the Actions tab to finish, then hard-refresh (Ctrl+Shift+R, or Cmd+Shift+R on Mac). Browsers cache aggressively.

Folders starting with an underscore are missing

By default, Pages runs your files through Jekyll, which skips files and folders starting with _. Add an empty file named .nojekyll to the repo root to turn that off.

The Pages option says I need to upgrade

Your repo is private. Make it public under Settings → General → Danger Zone, or upgrade your plan.
